# Stem to MIDI

Sunoなどで分離したWAVステムを、編集可能なMIDIへ変換するためのローカルツールです。

最初のバージョンは **Tempo Lab** と、単音ステム向けの **Raw MIDI Lab** に限定しています。Tempo Labで拍グリッドを確定し、Raw MIDI Labでベースなどの音高を検出して、後工程で編集できるMIDIとJSONを保存します。

## 現在できること

- WAVファイルの読み込み
- BPMと拍位置の自動検出
- 体感テンポとMIDI量子化用の内部グリッドを分けて調整
- 波形上への検出拍・体感拍・内部グリッド表示
- BPMの手入力、半分・倍テンポ補正
- 先頭拍位置の10ms／50ms単位調整
- 先頭拍誤差と検出終了後の余白表示
- 体感拍または内部グリッドを選んだクリック付きプレビュー
- 確認開始位置の先頭拍追従、拍・小節頭スナップ
- 解析結果、体感拍、内部グリッドのJSON出力
- 保存済みtempo.jsonを読み込み、作業状態を復元
- Version 1 JSONの自動移行とVersion 2 JSONの再読み込み
- SHA-256、またはファイル名と長さによるWAV照合
- ベースなど単音中心のステムをpYINで音高追跡
- 30秒／60秒区間での先行検証と全曲解析
- 先頭拍／小節頭／自由位置からの解析開始
- プレビュー、クリック、音高検出、ピアノロールの開始位置同期
- pYINフレームと抽出音符を重ねたピアノロール表示
- Raw MIDIと検出ノートJSONの出力
- 音符の細切れ、低確信度、音域端への張り付き警告

現時点では固定テンポと単音ステム向けです。Sunoの「Follow tempo changes」に対応する可変テンポマップ編集、和音楽器、ドラム分類、楽譜出力は次段階です。

## JSONから作業を再開

WAVを選択した後、「保存済みtempo.jsonから作業を再開」を開いてJSONを選択します。

読み込んだJSONから、次の編集状態を復元します。

- 体感テンポ
- 内部グリッド倍率
- 先頭拍位置

拍時刻の配列はJSONから直接復元せず、上記の設定と現在のWAVの長さから再生成します。これにより、設定値と保存済み拍配列が食い違っていてもグリッドを一貫した状態に保てます。

元WAVのSHA-256が一致しない場合は警告し、確認チェックを入れるまで設定を適用しません。SHA-256がないJSONでは、ファイル名と音源の長さで簡易照合します。

## 体感テンポと内部グリッド

ハーフタイムに感じる曲では、体感テンポを72 BPM、内部グリッドを144 BPMのように分けられます。

- **体感テンポ**: 曲を聴いたときの大きな拍
- **内部グリッド**: ベースの8分音符や16分音符を量子化するための細かい拍

`÷2`と`×2`は、内部グリッドをなるべく維持しながら体感テンポを変更します。内部グリッド倍率は`×1`または`×2`から選択できます。

## Raw MIDI Lab

Streamlitのサイドバーから「Raw MIDI Lab」を開き、次の2ファイルを選びます。

1. ベースなど単音中心のWAVステム
2. Tempo Labで保存したtempo.json

最初は30秒または60秒だけ解析し、ピアノロールと品質指標を確認します。問題が少なければ全曲解析へ切り替えます。

調整できる項目は次のとおりです。

- 最低音・最高音
- 有声音の確信度
- 最短音符
- 同音内で埋める短い無音
- 同じ音程を弾き直したときのオンセット分割
- 解析開始基準

出力されるMIDIはまだ量子化しません。WAV先頭からの絶対時間を保ったRaw MIDIで、tempo.jsonの内部グリッドBPMと先頭拍マーカーを含みます。同時に検出ノートJSONを保存し、次のClean MIDI工程で再利用します。

この初期実装は`librosa.pyin`を使用します。実際のベースステムで精度を測り、単音方式では不足する場合にBasic Pitchなどの多音対応バックエンドを追加します。

## セットアップ

Python 3.11以上を使用します。

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -e ".[dev]"
```

## 起動

```bash
streamlit run app.py
```

ブラウザでTempo LabまたはRaw MIDI Labを選択します。

## テスト

```bash
pytest
ruff check .
```

## データ管理

音源や生成物はGitへコミットしません。ローカルでは次のような構成を推奨します。

```text
workspace/
├─ input/
│  └─ song-name/
│     ├─ fixed/
│     └─ follow/
└─ output/
```
