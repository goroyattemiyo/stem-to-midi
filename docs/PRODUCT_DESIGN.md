# Stem to Score 製品設計

最終更新: 2026-08-05

## 1. 製品の目的

このプロジェクトの目的は、Audio-to-MIDIそのものではない。

**Sunoなどで生成した曲を、人が読んで演奏し、後から修正できる楽譜へ仕上げること**を目的とする。

```text
Sunoで良い曲ができる
  ↓
完成音源、ステム、または外部MIDIを読み込む
  ↓
テンポ、拍、小節を確定する
  ↓
演奏情報を楽譜用の音符へ整理する
  ↓
アプリ内で五線譜を確認する
  ↓
怪しい小節だけ修正する
  ↓
MusicXML / MIDI / Score JSONへ出力する
```

リポジトリ名は当面`stem-to-midi`のままとする。画面上の製品名は仮に **Stem to Score** とする。

## 2. 解決する問題

Audio-to-MIDIサービスや転写モデルは、音源を再生したときの再現性が高くても、そのMIDIを楽譜ソフトへ読み込むと次の問題が起こりやすい。

- 16分音符や32分音符が過剰に増える
- 数十msの隙間が短い休符になる
- 小節をまたぐ不自然なタイが増える
- 前ノリ、後ノリ、ビブラートが別音符として記譜される
- メロディ、ベース、コード、倍音が同じトラックへ混ざる
- テンポや拍子が正しくても、楽譜として読みづらい
- テンポや拍子自体がMIDIに含まれず、小節位置が崩れる

本製品は、MIDIの全イベントを忠実に表示するのではなく、次の4条件を同時に満たす譜面を作る。

1. 原曲らしさが残る
2. 人間が読める
3. 人間が演奏できる
4. 後から修正できる

## 3. 製品原則

### 3.1 演奏データと楽譜データを分ける

演奏の微細なタイミングを保持する`Performance Notes`と、楽譜表示用の`Score Events`を分離する。

譜面上では8分音符に整理しても、元の開始秒、終了秒、確信度、検出方法は失わない。

### 3.2 正確さだけでなく読みやすさを最適化する

単純に最寄りグリッドへ丸めない。複数の譜面候補を作り、次の要素で採点する。

```text
タイミング誤差
+ 32分音符の数
+ 短い休符の数
+ タイの数
+ 連符の数
+ 小節内の音符密度
+ 前後フレーズとのリズム不一致
```

UIではこの重みを「原音忠実 ↔ 読みやすい」のスライダーとして表現する。

### 3.3 変換方式に依存しない

入力候補は限定しない。

- Accuracy Labで生成したBasic Pitch MIDI
- Raw MIDI Labで生成したpYIN MIDI
- OpenMusicなど外部サービスのMIDI
- DAWや人手で作成したMIDI
- 将来追加する別の転写バックエンド

すべてを共通のPerformance Notesへ正規化し、その後のScore Compilerで処理する。

### 3.4 完全自動より、少ない確認で完成させる

全小節を手修正させない。自動処理が迷った小節だけを提示する。

```text
第24小節
A: 原音誤差 14ms、32分音符あり
B: 原音誤差 31ms、16分音符まで
C: 原音誤差 62ms、8分音符中心
```

ユーザーは楽譜を見て試聴し、候補を選ぶ。

### 3.5 中間データを正本にする

MIDI、MusicXML、ABC、PDFを編集データの正本にはしない。

- `tempo.json`: 時間軸の設定
- `performance.json`: 検出された演奏情報
- `score.json`: 楽譜として整理・編集された情報
- MIDI / MusicXML / ABC: score.jsonから生成する交換形式
- PDF / SVG: 表示・印刷用の派生成果物

## 4. ユーザーフロー

### 4.1 通常フロー

```text
新規プロジェクト
  ↓
音源またはMIDIを追加
  ↓
対象パートを選択
  ↓
自動でテンポと先頭拍を推定
  ↓
楽譜を生成
  ↓
Score Labで確認
  ↓
問題小節だけ修正
  ↓
MusicXMLをMuseScoreまたはFlatへ渡す
```

通常ユーザーにTempo Lab、Raw MIDI Lab、Accuracy Labを順番に操作させない。

### 4.2 高度なフロー

自動結果が悪い場合だけ、診断画面を開く。

```text
Beat Setup
  ↓
Transcription Diagnostics
  ↓
候補MIDIを比較
  ↓
Score Labへ戻る
```

## 5. 画面構成

## 5.1 Project Import

入力を1つのプロジェクトへまとめる。

対応予定:

- 完成音源WAV / MP3
- 分離済みWAVステム
- 外部MIDI
- `tempo.json`
- `performance.json`
- `score.json`

入力したファイルをSHA-256、ファイル名、長さで関連付ける。

## 5.2 Beat Setup

現在のTempo Labを再利用する。

役割:

- 体感テンポ
- 内部グリッド
- 拍子
- 先頭拍
- 小節位置
- 将来の可変テンポマップ

通常は自動結果を使い、失敗時だけユーザーが修正する。

## 5.3 Transcription Diagnostics

現在のRaw MIDI LabとAccuracy Labを、一般向けの主要画面から開発・診断画面へ位置付け直す。

役割:

- pYINとBasic Pitchの比較
- 外部MIDIの解析
- 発音漏れ、細切れ、長い空白、オクターブ跳躍の確認
- Performance Notesの生成

ここで最終楽譜を作らない。

## 5.4 Score Lab

本製品の中心画面。

```text
┌────────────────────────────────────────┐
│ 曲名 / パート / BPM / 拍子              │
├────────────────────────────────────────┤
│ 原音忠実 ───────●────── 読みやすい     │
│ 最大細分: 8分 / 16分 / 32分             │
│ 短い隙間: 吸収 / 休符 / スタッカート    │
├────────────────────────────────────────┤
│                                        │
│             五線譜プレビュー            │
│                                        │
├────────────────────────────────────────┤
│ 波形 / ピアノロール / 再生カーソル      │
├────────────────────────────────────────┤
│ 問題小節: 8, 17, 24                     │
│ 候補A / 候補B / Rawへ戻す               │
├────────────────────────────────────────┤
│ MusicXML / MIDI / Score JSON             │
└────────────────────────────────────────┘
```

最初から本格的な五線譜エディターは作らない。

初期編集機能:

- 小節を選択
- 譜割り候補を変更
- 音程を半音上下
- 音符を削除
- 隣接する音符を結合
- 音符を分割
- Rawの状態へ戻す
- ユーザー確認済みにする

## 6. Score Compiler

Score CompilerはPerformance NotesをScore Eventsへ変換する中核処理である。

### 6.1 処理順

```text
Performance Notes
  ↓
対象声部の選択
  ↓
短い誤検出の除去
  ↓
同音間の短い隙間を結合
  ↓
ビブラート、しゃくり、倍音候補の統合
  ↓
フレーズ境界の推定
  ↓
開始位置候補を生成
  ↓
終了位置と休符候補を生成
  ↓
小節ごとに複数の譜割り候補を生成
  ↓
音響誤差と譜面複雑度で採点
  ↓
Score Events
```

### 6.2 譜面複雑度

次の要素にコストを与える。

- 32分音符
- 32分休符
- 短い休符
- 小節をまたぐタイ
- 連符
- 1拍内の過剰な音符数
- 前後小節と異なるリズム型
- 非常に短い装飾音

32分音符を禁止するのではない。同じ細かいパターンが繰り返され、原音との差が大きくなる場合だけ採用する。

### 6.3 短い隙間

短い無音を常に休符にしない。

候補:

1. 前の音を伸ばす
2. 次の音を早める
3. 音価は伸ばし、スタッカートを付ける
4. 本当の休符として残す

隙間の長さ、拍位置、前後の音高、同音かどうかで選択する。

### 6.4 反復からの補正

同じリフやサビの反復を検出し、譜割りの多数決を行う。

同じフレーズの3回中2回が同じリズムなら、残り1回の数十msの違いを演奏揺れとして吸収できる。

## 7. データアーキテクチャ

```text
tempo.json
  └─ 秒 ↔ 拍 ↔ 小節の変換

performance.json
  └─ 元音源またはMIDIから得た演奏イベント

score.json
  ├─ 楽譜上の位置と音価
  ├─ 元イベントへの参照
  ├─ 自動補正理由
  ├─ 候補
  └─ ユーザー確定状態

score.json
  ├─ Clean MIDI
  ├─ MusicXML
  ├─ ABC
  └─ SVG / PDF
```

`score.json`の詳細は[SCORE_JSON.md](SCORE_JSON.md)に定義する。

## 8. 楽譜プレビュー

初期実装では次の経路を採用する。

```text
score.json
  ↓
MusicXML
  ↓
Verovio
  ↓
SVG
  ↓
Streamlit上に表示
```

Verovioはプレビュー用レンダラーであり、編集データ本体にはしない。

将来、音符選択や細かな操作が必要になった場合は、OpenSheetMusicDisplay、VexFlow、専用Webコンポーネントを比較する。

## 9. MVPの範囲

### 対応する

- 固定テンポ
- 4/4
- 単旋律1パート
- MIDI入力
- Accuracy LabのメロディMIDI入力
- 外部MIDI入力
- 四分、八分、16分音符
- 付点音符
- 休符
- 小節をまたぐタイ
- 五線譜プレビュー
- Score JSON / Clean MIDI / MusicXML出力

### 後回し

- 完成音源からの全パート自動総譜
- ピアノなどの複数声部
- コード譜
- 歌詞
- ドラム譜
- 変拍子
- 連符の本格対応
- 可変テンポ
- 五線譜上のドラッグ編集
- PDFの直接編集

## 10. 成功指標

音高正解率だけを成功指標にしない。

- 32分音符と32分休符の削減率
- 1小節あたりのタイ数
- 楽譜ソフトへ読み込んだ後の手修正回数
- ユーザーが確認する必要のある小節割合
- 元音源とClean MIDIのタイミング誤差
- 1曲をMusicXMLへ仕上げるまでの時間
- 同じ設定で再生成できる再現性

最終目標は、**Sunoで良い曲ができた後、専門的な採譜作業をせずに実用的な楽譜へ到達できること**である。
