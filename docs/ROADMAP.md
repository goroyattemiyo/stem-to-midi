# Stem to MIDI 開発ロードマップ

最終更新: 2026-08-04

## 1. 目標

分離済みWAVステムから、次の成果物を段階的に生成・修正できるローカルツールを目指す。

```text
WAVステム
  ↓
テンポ・拍・小節位置の確定
  ↓
Raw MIDI検出
  ↓
Clean MIDI生成
  ↓
人が修正できるScoreデータ
  ↓
MIDI / MusicXML / PDF / TAB譜
```

完全自動採譜だけを目標にしない。自動検出結果を可視化し、原音を聴きながら短時間で修正できることを重視する。

## 2. 開発原則

### 検証してから複雑化する

- まず30秒または60秒の区間で品質を測る。
- 誤りを「細切れ」「発音漏れ」「オクターブ違い」「拍ずれ」などに分類する。
- 問題が確認できてからモデルや補正処理を追加する。
- 高性能モデルを先に固定せず、同じ出力形式で比較できる構造にする。

### 時刻の基準を一つにする

- `first_beat_sec`を音楽上の基準位置とする。
- プレビュー、クリック、音高検出、ピアノロール、MIDI、将来の楽譜カーソルで同じ絶対時刻を使う。
- 拍、小節、音符位置の相互変換は共通ロジックに集約する。

### 中間データを残す

- テンポ設定は`tempo.json`へ保存する。
- Raw検出結果は`raw-notes.json`へ保存する。
- 将来は編集用の`score.json`を中心データにする。
- MIDIやMusicXMLを唯一の編集データにはしない。

### 事実・補正・推定を区別する

- 自動検出値とユーザー補正値を分けて保存する。
- AIが推定した音符、補正済み音符、ユーザー確定音符を識別できるようにする。
- 確信度や警告理由を後から確認できるようにする。

## 3. 現在地

### 実装済み

- 固定テンポのBPM・拍位置検出
- 体感テンポと内部グリッドの分離
- 先頭拍位置の手動補正
- 波形、拍線、クリック付きプレビュー
- tempo.jsonの保存・再読込
- Version 1 / Version 2 JSON対応
- WAV照合と不一致警告
- 単音ステム向けpYIN Raw MIDI検出
- 30秒／60秒／全曲解析
- ピアノロールと品質指標
- Raw MIDIとraw-notes.json出力
- プレビュー、クリック、検出開始位置の同期
- 先頭拍／小節頭／自由位置からの解析開始

### 現在の制約

- テンポは固定テンポのみ
- 音高検出は単音中心
- Raw MIDIは未量子化
- オクターブ補正、同音結合、短音除去は未実装
- 楽譜用の音価、休符、タイは未生成
- Score編集UI、MusicXML、PDF出力は未実装

## 4. 全体アーキテクチャ

```text
Tempo Lab
  └─ tempo.json
       ├─ felt_bpm
       ├─ grid_bpm
       ├─ first_beat_sec
       └─ time_signature

Raw MIDI Lab
  ├─ source.wav
  ├─ tempo.json
  └─ raw-notes.json / raw.mid

Clean MIDI Lab
  ├─ raw-notes.json
  ├─ tempo.json
  └─ clean-notes.json / clean.mid

Score Editor
  ├─ clean-notes.json
  ├─ score.json
  ├─ WAVプレビュー
  └─ 五線譜・TAB・入力グリッド

Export
  ├─ MIDI
  ├─ MusicXML
  └─ PDF
```

## 5. マイルストーン

## M1: 実ベースステムでRaw MIDI品質を測る

### 実施内容

- ベースが明確に鳴る30秒区間を複数選ぶ。
- 初期設定と調整後設定の`raw-notes.json`を保存する。
- 原音、クリック、ピアノロール、MIDI再生を比較する。

### 測る項目

- 検出音符数
- 有声音率
- 中央確信度
- 中央音長
- 1分あたりの音符数
- 最低・最高音への張り付き
- 100ms未満の短音比率
- 拍からの開始位置誤差
- オクターブジャンプ回数

### 完了条件

- 誤りの主要因を上位2〜3種類へ分類できる。
- pYINを継続するか、別バックエンド比較が必要か判断できる。
- Clean MIDIの処理順を実データから決められる。

## M2: Clean MIDI Lab

### 最初に実装する処理

1. 内部グリッドへの開始位置量子化
2. 短すぎる音の除去
3. 短い隙間を挟んだ同音の結合
4. 単音モードでの重複整理
5. 想定音域を使ったオクターブ候補補正
6. 音符終了位置の整理

### UI

- RawとCleanのピアノロール重ね表示
- 補正前後の差分一覧
- 各処理のON／OFF
- 量子化単位: 四分、八分、16分
- 補正結果の試聴
- Clean MIDIとclean-notes.json出力

### 完了条件

- DAW上で手修正量がRaw MIDIより明確に減る。
- 補正理由を音符単位で確認できる。
- 補正を無効化してRawへ戻せる。

## M3: 転写バックエンド比較

pYINで不足する問題が確認された場合に実施する。

### 候補

- pYIN: 単音向けの基準方式
- Basic Pitchなど: 多音・残響・倍音への比較候補
- 将来的な楽器別モデル

### 比較方法

同一区間・同一音域で、各バックエンドを共通の`raw-notes.json`形式へ変換する。

### 完了条件

- 音程正解率だけでなく、細切れ率、発音漏れ、処理時間、修正量で比較できる。
- 楽器ごとの既定バックエンドを決められる。

## M4: Score JSON

MIDIと楽譜編集UIの間に置く編集用データ形式を定義する。

### 最小データ例

```json
{
  "schema_version": 1,
  "tempo": 100,
  "time_signature": [4, 4],
  "first_beat_sec": 2.32,
  "instrument": "bass",
  "tuning": ["E1", "A1", "D2", "G2"],
  "measures": [
    {
      "number": 1,
      "events": [
        {
          "id": "note-1",
          "position": "0/16",
          "duration": "4/16",
          "pitch": 42,
          "string": 4,
          "fret": 9,
          "confidence": 0.91,
          "status": "detected"
        }
      ]
    }
  ]
}
```

### 必須要件

- 安定したイベントID
- 小節内位置と絶対秒の相互変換
- 音高、音価、休符、タイ
- ベース弦・フレット候補
- 自動検出／自動補正／ユーザー確定の状態
- Undo／Redo用の変更履歴
- スキーマVersion管理

### 完了条件

- Clean MIDIからScore JSONへ変換できる。
- Score JSONからMIDIを再生成して位置が一致する。
- 保存・再読込で編集状態を失わない。

## M5: ベース楽譜編集MVP

### 画面構成

```text
┌──────────────────────────────────────┐
│ 五線譜 + TABプレビュー              │
│ 再生 / 停止 / 速度 / ループ          │
├──────────────────────────────────────┤
│ 原音波形 + 再生カーソル              │
│ 選択音符の前後を即時試聴             │
├──────────────────────────────────────┤
│ 小節 × 拍 × 4弦のTAB入力グリッド     │
│ 検出候補、警告、確信度、修正操作      │
└──────────────────────────────────────┘
```

### 上段: 楽譜プレビュー

- 五線譜とTABを同時表示
- 再生位置をハイライト
- 小節番号、テンポ、拍子、チューニングを表示
- 表示・再生エンジンの候補としてalphaTabを検討する
- 編集データ本体はScore JSONとし、表示ライブラリへ依存させない

### 中段: 原音確認

- WAV波形と拍・小節線
- 選択音符の前後0.5〜1秒を即時再生
- 原音のみ、クリック付き、MIDI付きの切り替え
- 速度50〜150%
- 区間ループ

### 下段: 入力グリッド

- 4弦ベースを既定とする
- 数字キーでフレット0〜24
- 矢印キーで移動
- Tabで次の位置
- Backspaceで削除
- `r`で休符
- コピー、貼り付け、Undo、Redo
- AI候補は薄色、低確信度は警告枠、確定後は通常表示

### 最初の対応範囲

- 4/4固定
- ベース4弦標準チューニング
- 単音
- 四分、八分、16分
- 休符
- 小節をまたぐタイ
- MIDIとMusicXML出力

### 後回し

- 和音
- 複数声部
- 連符
- 変拍子
- 任意チューニング
- スライド、ハンマリング、プリングなどの奏法記号
- 五線譜上の直接ドラッグ編集

### 完了条件

- 検出結果を原音と同期しながら修正できる。
- 4小節程度のベース譜をキーボード中心で編集できる。
- 保存したScore JSONを再読込できる。
- MIDIとMusicXMLを出力できる。

## M6: MusicXMLとPDF

### 処理

- 小節分割
- 音価と休符の決定
- 小節をまたぐタイ
- 音部記号
- 調号と臨時記号
- 楽器名、テンポ、拍子
- TAB情報

### 出力

- `.mid`: DAW編集・再生
- `.musicxml`: 楽譜ソフトでの編集
- `.pdf`: 閲覧・印刷

PDFはMusicXMLから楽譜レンダラーを通して生成する。PDFを直接の編集形式にはしない。

### 完了条件

- 1パートのベース譜を楽譜ソフトで開ける。
- 小節線、休符、タイ、TABが実用上読める。
- PDFとMIDIの再生位置が一致する。

## M7: 楽器別展開

### 主旋律・ボーカル

- ビブラート吸収
- 音程変動の平滑化
- 歌メロとしての音符分割
- 歌詞は別段階

### ドラム

- 打点検出
- キック、スネア、ハイハット分類
- General MIDI Drum Mapへの変換
- 打楽器譜表現

### ギター・ピアノ

- 多音検出
- 和音整理
- 声部分離
- ギターでは弦・フレット割当

### 完了条件

- 楽器ごとに異なる検出・クリーニング設定を持てる。
- 共通Score JSONへ変換できる。

## M8: 可変テンポと総譜

### Fixed / Follow比較

- 同一曲のFixed版とFollow版を比較
- 拍位置差をグラフ化
- 固定グリッドで許容できない区間を特定

### 可変テンポ

- 区間ごとのBPM
- テンポイベント
- 小節頭の手動修正
- MIDIテンポマップとMusicXMLへの反映

### 総譜

- パート間の時刻統合
- パート名と譜表設定
- 総譜MusicXML
- パート譜PDF

## 6. 技術構成の段階移行

### 現在

```text
Streamlit
  ├─ Tempo Lab
  └─ Raw MIDI Lab

Python
  ├─ librosa
  ├─ NumPy
  ├─ Mido
  └─ Matplotlib
```

Streamlitは解析パラメータとデータ形式の検証に使う。

### Score Editor段階

```text
Pythonバックエンド
  ├─ 音声解析
  ├─ MIDIクリーニング
  ├─ Score変換
  └─ MusicXML生成

Webフロントエンド候補
  ├─ React / TypeScript
  ├─ 独自TAB入力グリッド
  ├─ 楽譜プレビュー
  ├─ 音声・MIDI再生同期
  └─ Undo / Redo
```

キーボード入力、細かな選択状態、Undo／Redo、再生カーソル同期が必要になった時点で、編集画面をStreamlitから専用Webフロントへ分離する。

## 7. 直近の実装順

1. 実ベースWAVで30秒区間を検証する
2. `raw-notes.json`から誤りの種類を集計する
3. Clean MIDI Labの最小処理を実装する
4. Raw／Clean差分を試聴・可視化する
5. ベース1曲でClean MIDIを確定する
6. Score JSON Version 1を定義する
7. 4小節のベースTAB編集MVPを作る
8. MusicXML出力へ接続する

## 8. 判断待ちの項目

- pYINだけでベース採譜に十分か
- Basic Pitchなどとの比較が必要な誤りは何か
- 量子化の既定値を八分と16分のどちらにするか
- スウィング・三連符をいつ導入するか
- Score EditorをStreamlitで試作してからReactへ移すか、最初から分離するか
- alphaTabを表示・再生プレビューへ採用するか
- PDF生成をローカル楽譜ソフト連携にするか、アプリ内処理にするか

これらは実音源の修正量と操作時間を測って決定する。
